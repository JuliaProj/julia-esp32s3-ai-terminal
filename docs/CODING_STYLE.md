# Julia UI 注释规范

本文规定 Julia UI 后续所有 C 代码的注释内容与 Doxygen 验收要求。注释使用中文，RGB565、Alpha、DMA、SPI、OTA、ISR 等技术术语保留标准英文。注释应解释契约、原因和约束，不重复翻译代码。

## 1. 文件级注释

每个 `.c` 和 `.h` 文件必须在首个 include guard 或 `#pragma once` 之前注明：

- 文件名和一句话核心职责，必须具体说明其管理或转换的对象。
- 作者、首次交付日期和 `主版本.次版本.修订版本`。
- 线程安全模型、内存所有权、动态分配和阻塞行为。
- Flash、SD、网络、LCD、DMA、SPI 等硬件或系统依赖。
- 直接依赖的项目头文件和关键第三方头文件。
- 使用该文件接口的模块，以及重要的依赖方向限制。

禁止使用“这是配置文件”“处理数据”“工具函数”等不能形成维护边界的描述。

## 2. 对外函数注释

每个公开函数和回调类型必须包含：

- 一句话功能和可观察副作用。
- 每个输入参数的方向、含义、单位、有效范围、NULL 规则和所有权。
- 每个输出参数的方向、写入条件、单位、有效期和所有权。
- 可选参数的默认行为。
- 成功返回值、全部可预期失败返回值及其触发条件。
- 初始化顺序、任务上下文、线程安全和 ISR 调用限制。
- Flash 擦写、文件 I/O、网络、阻塞、重启或全局状态修改等警告。
- 不包含 C 实现代码的典型使用场景，以及相关函数名称。

无参数函数也必须说明无输入参数；无失败路径的函数必须明确“无错误码”或“当前实现始终返回”的契约。

## 3. 结构体与枚举注释

结构体必须说明整体用途、生命周期和所有权。每个字段必须说明含义、单位、范围、NULL/NUL 规则、默认值来源和修改影响；关联字段应注明一致性约束。字段变化会要求加载器、校验器、序列化器或消费者同步修改时，必须明确列出。

枚举必须说明整体用途。每个枚举值必须说明状态含义、有效阶段、产生方和消费方；用作数组索引或持久化值时，必须注明禁止重排或复用数值。

## 4. 宏注释

每个公开宏和影响资源占用的私有宏必须说明：

- 宏的含义和单位。
- 编译期只读或运行时可覆盖属性。
- 合法范围及越界风险。
- 修改后影响的 RAM、Flash、性能、协议兼容性或硬件行为。

接口版本必须拆分为 `*_VERSION_MAJOR`、`*_VERSION_MINOR`、`*_VERSION_PATCH` 三个整数宏，使依赖方能够执行编译期检查。

## 5. 复杂代码块注释

状态恢复、原子切换、缓冲区复用、并发协调和性能敏感算法前必须说明：

- 为什么需要这一步以及它防止的故障。
- 必须满足的前置条件和执行顺序。
- 完成后必须成立的条件。
- 修改的共享状态、资源所有权和失败清理责任。
- 时间、内存或帧预算，以及禁止执行的上下文。

代码变更后若上述原因或约束失效，必须同步更新注释。

## 6. 语言与格式

- 使用简洁、完整的中文句子，技术术语保留标准英文。
- 对外契约使用 Doxygen 的 `@file`、`@brief`、`@param`、`@return`、`@pre`、`@warning`、`@note` 和 `@par`。
- `@param` 必须标记 `[in]`、`[out]` 或 `[in,out]`。
- 单位使用明确符号，如像素、毫秒、Hz、MHz、bit/s、字节和百分比。
- 注释与符号放在同一处维护，不复制容易失真的实现细节。

## 7. 禁止风格

- 禁止只复述赋值、循环、条件分支或函数名已经表达的动作。
- 禁止无参数、返回值或错误码说明的公开接口注释。
- 禁止拼音、网络用语、情绪化内容、过期 TODO 和个人调试记录。
- 禁止声称“线程安全”“原子”“不阻塞”，除非实现或外部约束确实保证。
- 禁止在注释中隐藏未实现需求；未实现能力应进入任务或限制文档。
- 禁止为补注释而在渲染循环加入日志、分配或其他行为变化。

## 8. Doxygen 生成与检查

本项目提供根目录 `Doxyfile`。安装 Doxygen 后，在仓库根目录执行 `doxygen Doxyfile`；本地存在便携版 `tools/doxygen/doxygen.exe` 时也可直接使用。HTML 首页位于 `build_doxygen/html/index.html`，告警日志位于 `build_doxygen/doxygen-warnings.log`。

配置输入包含 `main/config`、`main/events` 和 `main/ota` 的六个接口文件，并开启未记录成员、参数不匹配、文档错误和不完整参数告警。`WARN_AS_ERROR` 设置为 `FAIL_ON_WARNINGS`，因此任何注释告警都会使命令失败。生成目录属于构建产物，不提交生成的 HTML。

## 9. 验收清单

- 每个 `.c/.h` 均包含职责、作者、日期、版本、约束、依赖和消费者。
- 每个公开 API 均包含完整参数、返回值、错误码、上下文和危险操作说明。
- 每个结构体字段、枚举值和宏均包含所需信息。
- 复杂逻辑解释原因、顺序和副作用。
- 注释使用中文，技术术语使用标准英文。
- 版本宏可被依赖模块在编译期检测。
- Doxygen 生成无警告，且注释与当前实现一致。
